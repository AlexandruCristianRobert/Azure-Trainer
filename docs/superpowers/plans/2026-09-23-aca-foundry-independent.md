# Foundry Independent Lab implementation plan

> REQUIRED: superpowers:subagent-driven-development; implement and review each task in order.

**Goal:** Deliver journey Lab12, `aca-foundry-independent`, in which the learner independently wires a second supported Foundry deployment to a different API contract through a **dedicated inference identity**, under an eight-second maximum request budget, and proves valid, invalid, transient and persistent behavior. The Lab must accept multiple supported policy choices that meet the contract. No Bicep Lab is started in this increment.

**Architecture:** Reuse the AIServices account/project/deployment sandbox and deterministic Responses simulator. Extend ACA identity modeling to attach an additional user-assigned identity while retaining the registry-pull identity, using the documented `az containerapp identity assign` form. Add a versioned `POST /api/brief` project whose source/config parser captures a bounded contract and variable but compliant retry policy. Generalize only the named-request path to support this second contract; no arbitrary HTTP body or outcome injection. Seed a healthy private API, ACR and pull identity, plus a separate unattached inference identity, but no Foundry resources or earned evidence. Native evidence binds active source/policy, intended deployment and exact caller identity/grant.

Preserve dirty baseline; no staging, commits, file deletion, git metadata edits or package installation. Sol medium task implementers and Terra medium scoped/whole-Lab reviewers, sequential writers. Root performs integration/guarded delivery. Use pre-task snapshots/diffs for review.
- Bind to [agreed journey design](../specs/2026-09-22-containerapps-learning-journeys-design.md), [technical design](../specs/2026-09-22-containerapps-learning-journeys-technical-design.md) and ADR-0002. Preserve Lab10/11 manifest/content versions, existing nine earlier journey Labs, six legacy Labs, native Results/Restart, assistance and no-op evidence behavior.
- Keep the coherent Foundry account resource endpoint `/openai/v1/`, Responses API, token scope `https://ai.azure.com/.default`, SDK retries disabled, pinned `OpenAI` 2.12.0 and `Azure.Identity` 1.21.0, `Microsoft.CognitiveServices/accounts@2025-06-01`, and model profile `gpt-5-mini`/`2025-08-07`/`GlobalStandard` as a **simulated fixture**. Independent uses a new account/project and account deployment name `briefing-secondary` (distinct from model name and previous Labs), not a claim of live availability.
- Independent API contract is `POST /api/brief` with JSON input `{content:string}`. Empty/whitespace or over-limit content returns 400 before inference; valid returns 200 `{brief,deployment}` after an actual correlated attempt to `briefing-secondary`. Retryable persistent failure returns 503 after bounded exhaustion. The fixed request fixtures cannot be edited to inject a status, trace, duration or fault.
- Require a dedicated inference UAMI different from the existing ACR pull UAMI. Both must be attached to the Container App, `registryIdentity` must remain the pull UAMI, active `AZURE_CLIENT_ID` must select the inference UAMI, and only its principal with the approved `Cognitive Services User` role at exact account scope can authorize the model call. The account's project-management identity and ACR pull grant cannot substitute. Per [ACA managed-identity guidance](https://learn.microsoft.com/en-us/azure/container-apps/managed-identity), adding an identity alone does not restart/create a revision; the saved source/config and active deployment still control request behavior.
- Accept multiple **supported** compliant policies, not one literal worked answer: two or three total attempts, total budget five through eight seconds, per-attempt cap one or two seconds, `HonorRetryAfter=true`, Retry-After honored when affordable and deterministic fallback otherwise. Reject these violations at parse/build time. Fixture timings must make both allowed attempt counts finish inside even the five-second budget: 100ms attempts, 1s/2s fallback waits for persistent 429, and a 1s Retry-After followed by a 100ms success for transient 429. Test oversized Retry-After falling back within the active budget. Assert elapsed time is at most the active budget; invalid input must cause zero attempts. Reject one attempt, >three attempts, >eight seconds, SDK retries or authorization/config retries. Alternative supported policy choices must be exercised in tests.
- Keep management and data-plane identity separate. Changes to active source/config, selected inference identity, account/deployment or exact grant invalidate relevant proof, including away/back. Draft/save/build-only changes and semantic no-ops preserve it. A completed Result stays read-only and Restart starts with no inherited proof.

## Review focus

1. Multi-UAMI ACA modeling preserves existing single-identity JSON and ACR behavior. Adding the inference identity does not remove the pull identity or create a revision by itself; deleting an attached identity cannot leave effective access. CLI uses the documented `az containerapp identity assign --user-assigned <id>` form and exposes both IDs. No unsupported system-identity semantics are silently implied.
2. The second API contract is genuinely distinct. The simulator derives route, input field and output field from the **active parsed project**, not the fixture's expected status. The only callable routes/bodies are versioned named scenarios; invalid input short-circuits even without model access and cannot earn completion until intended active setup exists.
3. The caller selected through captured `AZURE_CLIENT_ID` is the dedicated inference UAMI. Granting the pull UAMI, management identity, wrong project/account scope or wrong deployment cannot pass. Only the approved `Cognitive Services User` account-scoped role qualifies.
4. At least two different compliant attempt/budget/cap combinations pass the same four proofs. Too-large budgets, one attempt, no Retry-After handling, returned canned 200, stale image and stale grant fail. Public 503/diagnostics remain distinct from upstream 429; 401/403/404 never retry.
5. Full native persistence, assistance, Result/Restart, routing and earlier Foundry/ACA regressions hold. Simulation limitations are visible; visual browser QA is reported honestly if no browser is attached.
