- Build and publish capture saved application files. Apply captures saved manifests. Running containers retain their captured image and environment.
- PostgreSQL, pgvector, documents, embeddings and AI responses are supplied fixtures. Database administration and dedicated Workload Identity/Key Vault work remain deferred.
- Deliver and review one Lab at a time.
- Preserve all legacy and Container Apps Labs, saved runs and Lab Results.
- Journey/versions: aks-knowledge-assistant, containers, aks, engineVersion 2, contentVersion 1; IDs/orders `aks-config-guided`/4, `aks-config-troubleshooting`/5, `aks-config-independent`/6.
- Each Task has two optional Hints, complete structured Solution steps and an Exam Note. A supplied fixture is visibly identified, not silently created by a deployment command.
- Changing configuration never edits an image artifact. A Python code change requires a new build/publication and explicit deployment of that image; a manifest change requires apply.

## Review Focus

1. Editing/applying an environment-backed ConfigMap or Secret must not update the environment of a running Pod; new/restarted Pods must receive the current values. Tasks 1, 3 and 5 test this.
2. A same-named ConfigMap/Secret in another namespace must not satisfy a reference or leak data. Tasks 1, 6 and 7 test this.
3. Mounted file propagation and application rereading are separate from env snapshots; unrelated edits and read commands must not advance propagation. Tasks 1-3 test this.
4. A canned answer must not bypass wrong endpoint, credential, collection or captured Python behavior; application diagnostics must not echo secret values. Tasks 2, 4 and 7 test this.
5. Restoring old settings, stale incident receipts, reload midway through a fault and the second instance's changes must not satisfy the wrong Task or invalidate the unaffected first instance. Tasks 3, 6 and 7 test this.

## Exact configuration behavior

Supported ConfigMap: v1, metadata, `data` string map; no binaryData/immutable in these six Labs. Supported Secret: v1, type Opaque, metadata, `data` strict base64 and `stringData` strings. Normalize stringData into data on apply, with stringData winning for a duplicate key. Explicit get -o yaml/json may show the fictional encoded data; describe and the Portal show keys only. Reject invalid encoding with a value-free diagnostic.

Deployment additions: `env[].valueFrom.configMapKeyRef` and `secretKeyRef` with name/key and optional boolean; optional references default false. Literal value and valueFrom are mutually exclusive. Add `volumes[].configMap` or `secret` with optional items key/path mappings, and matching container volumeMounts with an absolute mountPath and readOnly true. Reject duplicate env names, duplicate volume names/paths, escapes, subPath and unrelated volume types with explicit diagnostics. `envFrom` is explicitly unsupported in this increment and help identifies the supported key-reference syntax.

Resolve all references in the Pod namespace. Missing required ConfigMap/Secret/key prevents starting that container and yields a CreateContainerConfigError-style waiting reason with an event naming the resource/key, never its value. A missing required volume resource/key yields a FailedMount event and Pending Pod. A missing optional env value is omitted, allowing the Python default. Retry waiting Pods after relevant objects are applied; do not recreate already-running Pods when only data changes.

Capture resolved environment in podSnapshots at container creation. Capture mounted files and resource references separately. When mounted ConfigMap/Secret content changes, schedule `projectionDue[podUid] = simTimeMs + 60000`; coalesce later changes and project the latest content at the scheduled sync. The 60-second interval is a visible teaching simplification, not a real Kubernetes guarantee. Plain ConfigMap volume updates eventually project; subPath and application-side caching are not silently modeled as live updates.

New action `{type:'aks-advance',seconds:60}` advances only the declared local AKS simulation, with integer seconds 1-300 and no caller snapshots/outcomes. Expired projection deadlines refresh mounted files, not environment. The supplied Python settings() reads JSON on each request, so that particular application sees changed projected content on its next request. Wall-clock elapsed-time ticks and kubectl reads never flush projections.

`kubectl rollout restart deployment/NAME` updates the Pod-template restartedAt annotation using a deterministic timestamp based on simulation time plus a monotonic sequence tie-breaker, replaces Pods through existing reconciliation and captures new env/file values. A repeat restart is a new change; no-op apply of an unchanged manifest must preserve existing server-managed restart annotation. No clocks/secret values are supplied by the learner action.

Final app.py for Lab 4:

```python
import os
import json
from pathlib import Path
import training_runtime

SERVICE_NAME = "knowledge-assistant"
SERVICE_VERSION = "1.0"
PORT = 8080

def info():
    return {
        "service": SERVICE_NAME,
        "version": SERVICE_VERSION,
        "environment": os.environ.get("APP_ENV", "development"),
    }

def settings():
    display = json.loads(Path("/etc/assistant/settings.json").read_text())
    return {
        "environment": os.environ.get("APP_ENV", "development"),
        "ai_endpoint": os.environ.get("AI_ENDPOINT", ""),
        "answer_deployment": os.environ.get("ANSWER_DEPLOYMENT", ""),
        "embedding_deployment": os.environ.get("EMBEDDING_DEPLOYMENT", ""),
        "pg_host": os.environ.get("PGHOST", ""),
        "pg_database": os.environ.get("PGDATABASE", ""),
        "pg_user": os.environ.get("PGUSER", ""),
        "pg_password": os.environ.get("PGPASSWORD", ""),
        "collection": os.environ.get("COLLECTION", ""),
        "display_name": display["display_name"],
        "response_prefix": display["response_prefix"],
    }

def answer(question):
    return training_runtime.answer(question, settings())
```

Starter settings() intentionally maps pg_host from `POSTGRES_HOST` rather than `PGHOST`; the Guided code Task repairs the actual lookup. Include app code in build/publication before the initial configuration verification. The seed has a previously published working image, so the task must require the learner's newly built current saved source, not accept the seed artifact.

server.py retains GET /api/info and adds POST /api/ask: parse a JSON object with a question string, call app.answer, and serialize its status/body. Invalid JSON/shape yields 400. The helper's complete Python fixture source is generated as a readable string from the same versioned literal fixture data used below, then checks settings, looks up vectors/documents, applies collection filtering, ranks by cosine similarity and returns the canned result for the selected source. It is labeled a teaching fixture adapter, not a network client or Azure SDK. The browser never executes this Python helper; it projects validated helper use to simulateAssistant. Keep its source/digest fixed per manifest so changing the helper cannot forge passing evidence.
