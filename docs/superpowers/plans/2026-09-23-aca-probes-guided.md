# Guided health probes implementation plan

> **For agentic workers:** REQUIRED: superpowers:subagent-driven-development. Deliver only Lab7 and its prerequisites, review and verify it before planning Lab8.

**Goal:** Teach separate startup, readiness and liveness behavior through supported endpoint edits, captured probe configuration, and measured per-replica experiments.

**Architecture:** Extend the existing bounded .NET project parser and saved-file deployment route; add an isolated probe runtime and reuse scenario actions/evidence/persistence. Integrate one Guided Lab with Files, Experiment Controls and read-only Blade inspection.

**Tech stack:** Existing Vue3/Pinia/Vitest/Vite JavaScript; no new dependencies, arbitrary C# execution or network calls from the simulator.

**Spec:** ADR-0002 and `docs/superpowers/specs/2026-09-22-containerapps-learning-journeys-{design,technical-design}.md`, especially approved probe flows and technical sections5–8/13.

- Probe shape: `{type:'Startup'|'Readiness'|'Liveness',httpGet:{path,port,scheme:'HTTP'},initialDelaySeconds,periodSeconds,timeoutSeconds,failureThreshold,successThreshold}`. Integers: port1..65535, delay1..60, period/timeout1..240, failure/success1..10; Startup/Liveness successThreshold1. Require distinct types, at most one each; empty/missing probes may be deployed but cannot pass Tasks. HTTP200..399 succeeds.
- Absent Readiness is treated as a successful check after configured startup gating; absent Startup does not gate. This does not inject default probe configuration. Lab grading still requires all three configured probes and correct endpoint behavior.
- Teaching semantics: startup gates readiness/liveness until success; readiness controls traffic only; startup/liveness sustained failure restarts, clears process hang and resets startup/counters. Readiness and downstream faults persist across restart until the fixture clears them. One-second explicit clock; no wall-clock advancement; immediate simulated restart with no backoff/grace. This is a Kubernetes-aligned ACA teaching model, not a production timing guarantee.

## Review focus

1. A valid probe-file save must not silently update a deployment; malformed/unsupported YAML must not partly mutate resources. Task1 tests.
2. New health syntax must not make unrelated executable C# or legacy project edits silently valid; comments/whitespace and equivalent supported response forms should pass. Task1 tests.
3. Changing probes or deployed source during an experiment must abort it; stale evidence, no-op changes, failed update, deletion/recreation and round-trip settings need explicit coverage. Task2 tests.
4. Readiness must route around only the affected replica, recover without restart, and a process hang must clear only after liveness restart and new startup. Task2/3 tests.
5. Partial/pause/reload/cancel, always-successful endpoints, missing/disabled probes and excessively delayed detection cannot satisfy behavior Tasks. Task2/3 tests.
