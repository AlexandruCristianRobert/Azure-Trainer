# Data journey Labs 1–4 (Cosmos DB) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first four Data-journey Labs (Cosmos DB for NoSQL: SDK + RUs + indexing + consistency; vectors + change feed; Troubleshooting; Independent) on the Knowledge Assistant running in the simulated AKS cluster.

**Architecture:** Learner Python in marked edit zones is recognized by one shared SDK call catalog (ADR-0003) into a small op list per function. A data-app runtime executes those ops against Cosmos items held in the Sandbox, using a bounded Cosmos NoSQL query evaluator and a deterministic RU cost model. The app reaches the runtime only through the existing AKS pipeline: `az acr build` → edit `k8s/deployment.yaml` image → `kubectl apply` → Experiment Controls requests. Evidence is recorded through the existing `recordVerification` machinery.

**Tech Stack:** Vue 3, Pinia, Vite, `@lezer/python`, `yaml`, Vitest (targeted files only).

**Spec:** `docs/superpowers/specs/2026-09-30-data-learning-journey-discussion.md` (read it first). ADRs: `docs/adr/0002-behavioral-labs-with-bounded-local-simulation.md`, `docs/adr/0003-shared-sdk-call-catalog-for-data-labs.md`.

### Task 3: Cosmos NoSQL query evaluator

**Files:** Create `src/lib/data/cosmos-query.js`, `tests/data-cosmos-query.test.js`.

**Supported grammar (anything else → `DATA_UNSUPPORTED`):**
```
SELECT [TOP (n|@p)] (* | VALUE COUNT(1) | projection {, projection})
FROM c
[WHERE cond {AND cond}]
[ORDER BY (c.path [ASC|DESC] {, c.path [ASC|DESC]} | VectorDistance(c.path, @p))]
projection := c.path [AS alias] | VectorDistance(c.path, @p) [AS alias]
cond := c.path (= | != | < | <= | > | >=) (@p | literal) | ARRAY_CONTAINS(c.path, @p)
literal := 'string' | number | true | false
```

**Interfaces — Produces:**
```js
export function parseCosmosQuery(text)  // → { ast } | { error: { code: 'DATA_UNSUPPORTED'|'BadRequest', message } }
export function runCosmosQuery(container, text, parameters = [], { partitionKey } = {})
// → { rows, stats: { scanned, returned, partitionsTouched, usedIndex: boolean, vector: boolean, orderBy: string[] } }
// | { error: { code, message } }
```

Rules:
- `parameters` is `[{ name: '@x', value }]`; a missing parameter → `BadRequest: Parameter '@x' is not defined.`
- `usedIndex` is false if any WHERE/ORDER BY path is excluded by the container's `indexingPolicy` (match `excludedPaths` `"/path/*"` or `"/*"` without an explicit include). Scanned count = all items in scope when `usedIndex` is false; otherwise the matching items.
- Two or more ORDER BY paths require a matching `compositeIndexes` entry (same paths and orders, or all orders reversed), else the error `BadRequest: The order by query does not have a corresponding composite index that it can be served from.`
- `partitionsTouched` = 1 when `partitionKey` is given or WHERE has equality on the partition key path; otherwise `container.physicalPartitions`.
- `VectorDistance` returns cosine similarity for a cosine policy (higher = more similar; ORDER BY VectorDistance sorts descending, as Cosmos does for cosine). A vector parameter whose length differs from the policy dimensions → `BadRequest: The vector dimensions (12) do not match the vector embedding policy dimensions (8).`

### Task 4: Deterministic RU cost model

**Files:** Create `src/lib/data/cosmos-cost.js`, `tests/data-cosmos-cost.test.js`.

```js
export const CONSISTENCY_ORDER = ['Strong', 'BoundedStaleness', 'Session', 'ConsistentPrefix', 'Eventual']
export function readMultiplier(consistency)          // Strong|BoundedStaleness → 2, others → 1
export function pointReadCharge(item, consistency)   // ceil(sizeKB) * readMultiplier; size = JSON length of item without _ fields / 1024
export function writeCharge(item, indexingPolicy)    // round2(1.9 + 0.35 * indexedTerms(item, policy)); arrays count one term per element

export function applyThroughput(charges, provisionedRUs) // charges: number[] in one simulated second → { accepted: boolean[], retryAfterMs }
//   accept in order while the running sum ≤ provisionedRUs; the rest get 429 with retryAfterMs = 1000
```

### Task 5: Shared SDK call catalog + Python recognizer

**Files:** Create `src/lib/data/sdk-catalog.js`, `src/lib/data/python-sdk.js`, `tests/data-python-sdk.test.js`.

**Supported Python inside edit-zone functions** (a function is an edit zone if its name is listed in `manifest.editZones`):
- statements: `name = expr`, `return expr`, `for name in expr:` whose body contains only supported statements, an expression statement that is a call, and `if expr:` / `else:` with a comparison `is None`, `is not None`, `==`, `!=`, `<`, `>=`
- expressions: string/number/bool/None literals, function parameters, locals, module constants, dict literals with string keys, list literals, subscripts `x["k"]` / `x.get("k")`, attribute chain `name.attr`, calls to catalog entries or to other functions in the same file, `list(expr)`, `len(expr)`, `str(expr)`, `next(iter(expr), None)`, `embed(text)` (scaffold)
- everything else → `{ code: 'DATA_UNSUPPORTED', message: 'Not supported by the simulator: <construct>', path, line, column }`

**Catalog entry shape:**
```js
// sdk-catalog.js
export const SDK_CALLS = {
  'cosmos.CosmosClient': { kind: 'constructor', params: ['url', 'credential', 'consistency_level'], required: ['url', 'credential'] },
  'cosmos.container.read_item': { kind: 'method', receiver: 'cosmos-container', params: ['item', 'partition_key'], required: ['item', 'partition_key'] },
  'cosmos.container.query_items': { kind: 'method', receiver: 'cosmos-container', params: ['query', 'parameters', 'partition_key', 'enable_cross_partition_query', 'max_item_count'], required: ['query'] },
  'cosmos.container.upsert_item': { kind: 'method', receiver: 'cosmos-container', params: ['body'], required: ['body'] },
  'cosmos.container.create_item': { kind: 'method', receiver: 'cosmos-container', params: ['body'], required: ['body'] },
  'cosmos.container.delete_item': { kind: 'method', receiver: 'cosmos-container', params: ['item', 'partition_key'], required: ['item', 'partition_key'] },
  'cosmos.container.query_items_change_feed': { kind: 'method', receiver: 'cosmos-container', params: ['start_time', 'continuation', 'partition_key', 'max_item_count'], required: [] },
  'cosmos.container.last_continuation': { kind: 'attribute', receiver: 'cosmos-container', path: 'client_connection.last_response_headers["etag"]' },
}
export function lookupCall(receiverType, name) // → entry | undefined
```
Positional arguments map onto `params` in order. Unknown keyword → `DATA_UNSUPPORTED`. Missing required → diagnostic `TypeError: read_item() missing required argument 'partition_key'` (code `SDK_ARGUMENT`), which pins Review Focus #1.

The client's consistency is read from the fixed-or-editable `clients.py` `CosmosClient(..., consistency_level=...)` call (the recognizer parses `clients.py` too, and exposes `appSpec.data.client = { consistency }`).

- Produces:
```js
export function runDataFunction({ appSpec, sandbox, account, database, functionName, args, nowMs, scenarioState })
// → { sandbox, status: 200|400|404|409|429|500, value, error?: { code, message },
//     calls: [ { call, receiver, container, charge, consistency, stale: boolean, stats?, source } ],
//     totalCharge }
```

Semantics:
- Each receiver resolves to the container of the same name in `database` (receivers map to container names; `qa_history` → container `qa_history`). A missing container → `404 NotFound: Resource Not Found (container '<name>')`.
- The account default consistency comes from the Sandbox account. The effective consistency is the client's `consistency_level`, or the account default when it's null. A client level **stronger** than the account default (by `CONSISTENCY_ORDER` index) → status 400 with `BadRequest: Consistency level 'Strong' is stronger than the account default 'Session'.` (Review Focus #4).
- `read_item`: point read. If the effective consistency is `Eventual` or `ConsistentPrefix` and the item's `_ts` equals the current scenario's write time (`scenarioState.writesThisRequestSet` contains the id), return `_previous` and mark `stale: true` (the teaching approximation of replica lag). A missing item → 404 `CosmosResourceNotFoundError`. If `partition_key` doesn't match the item's partition value, it's also 404 (as in real Cosmos).
- `query_items`: without `partition_key` and without `enable_cross_partition_query=True`, a filter not on the partition key → 400 `BadRequest: Cross partition query is required but disabled.` (the classic Python SDK error). Otherwise run the evaluator and charge `queryCharge`.
- `upsert_item`/`create_item`: write via the store, charge `writeCharge`, and append to the change feed (Task 7).
- `query_items_change_feed` and `last_continuation`: delegate to `change-feed.js` (Task 7).
- Every call records into `calls`; `totalCharge` is the rounded sum.
