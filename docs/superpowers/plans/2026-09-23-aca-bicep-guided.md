# Guided Bicep implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver journey Lab 13, `aca-bicep-guided`, where a learner completes, previews, deploys, updates, and idempotently reapplies a modular Bicep project, then proves a Foundry request and a changed CPU scale ceiling from the active application. Do not start Labs 14â€“16 in this increment.

**Architecture:** Add a bounded Bicep lexer/parser, typed evaluator and module DAG; map its small pinned ARM schema subset to existing Sandbox resource operations through canonical desired-state adapters. `az deployment group` validate/what-if/create/show reads saved files, stores run-local preview/deployment provenance, and activates the app only after the graph succeeds. Register one Guided Lab with a seeded published image and `existing` ACR, a single app UAMI with separate ACR/Foundry grants, and native request/load evidence. Add a focused preview/provenance panel rather than changing the general project editor flow.

**Authority:** [Lab 13 implementation design](../specs/2026-09-23-aca-bicep-guided-implementation-design.md), [agreed journey](../specs/2026-09-22-containerapps-learning-journeys-design.md), [technical design](../specs/2026-09-22-containerapps-learning-journeys-technical-design.md), ADR-0002. Pinned API versions and supported field shapes are in the implementation design. This is a teaching simulation, not Azure execution or arbitrary Bicep support.
